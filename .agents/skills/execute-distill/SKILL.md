# execute-distill

从执行日志到 GTD 清单的蒸馏工具。适用场景：用户写完 journal 或 pull journal 后，需要将新内容转化为 GTD 清单条目。

## 工作路径

项目根：`/home/iguo/repos/quanttide/domains/quanttide-execute`

| 路径 | 说明 |
|---|---|
| `data/journal/default/<date>.md` | 原始思考流 |
| `data/journal/execution/<date>.md` | 执行日志 |
| `data/profile/index.md` | GTD 清单（目标文件） |

## 步骤

### 1. 读取输入

- 检查 `data/journal/default/` 和 `data/journal/execution/` 中的新文件（尚未蒸馏过的）
- 读取新文件内容
- 同时读取 `data/profile/index.md` 了解当前清单状态
- 读取 `data/context/gtd-workflow.md` 了解整理模式

### 2. 提取候选条目

逐条扫描日志，识别可转化为 GTD 条目的内容。提取规则：

| 原文线索 | 推定类型 | 推定优先级 |
|---|---|---|
| "xx日内要/需要/必须" | 悬而未决（有时限但路径不清） | 高 |
| "已经安排了/定了周X开会" | 日程 | 中 |
| "让XX去..." / "等XX回复" | 等待回复 | 中 |
| "我想一下/思考一下怎么..." | 悬而未决 | 中 |
| "查一查/调研一下" | 下一步行动 | 低 |
| "我觉得可以考虑..." / "也许可以..." | 跳过（尚不确定） | — |

每条候选条目包含：

- **事项**：提炼后的标题（简洁，一行）
- **类型**：日程 / 下一步行动 / 等待回复 / 悬而未决
- **优先级推定**：高 / 中 / 低
- **理由**：基于原文哪部分推断

### 3. 对比现有清单

检查候选条目与 `data/profile/index.md` 的关系：

- **新增**：清单中未出现过
- **合并**：与现有条目主题相关，可合并
- **移动**：类型或优先级应调整
- **跳过**：已在清单中且状态一致

### 4. 输出变更提案

用结构化格式呈现给用户确认：

```
📋 蒸馏提案——{日期}

[新增] {事项} → {板块} · {优先级}
[合并] {事项} → {板块}
[移动] {事项} → 从 {原板块} 移至 {目标板块}
[跳过] {事项} — 已在清单中

用户确认后执行写入。
```

### 5. 写入并提交

用户确认后：

- 更新 `data/profile/index.md`
- 在 `data/profile` 子模组中 commit
- 在父仓库中 commit 更新子模组引用
- 推送（可选）

### 6. （可选）

若用户要求，可在同一 session 中记录提炼心得。

## 注意事项

- 只提炼与**团队协作**相关的事项，不提炼纯个人思考
- 用户日志里说过："只管需要团队协作的部分，个人方法自便"
- 保持已有的板块结构：日程 → 下一步行动 → 等待回复 → 悬而未决
- 优先级用文字标注（`> 优先级：高/中/低`），不用符号
- 各板块内按优先级降序排列（高 → 中 → 低）
- 若提案为空（无新条目），告知用户，不做变更
